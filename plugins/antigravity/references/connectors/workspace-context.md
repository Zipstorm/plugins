# Keep connected work with its role

Before a connected task, resolve the SeekOut workspace and accepted role context.
Reuse its confirmed ATS job and source locations. A provider's project, team or
workspace is a separate identity. Ask only when the target is ambiguous.

Keep this small binding with the work in the current conversation: SeekOut
workspace ID, requested action, provider/account, source container and returned
record IDs/links. A pane change never retargets a pending send or event update.
Re-read relevant criteria and the external record when resuming delayed work.

For context gathering, bring back the decision or evidence with its source, date
and scope; save accepted role decisions in the role's trade-offs report
([plan a role](../report-building.md)). Do not copy whole conversations into it. For an external action, return the
resulting draft, event, document or task link and its confirmed status. Never
call a draft sent or a scheduled run completed.

A native link saves only when a supported workspace operation confirms it.
The existing ATS-job link does not provide general email, event or task linking.
Without a supported link action, keep the handoff in conversation and say that
it has not been saved to the workspace. Do not hide links in unrelated fields.

For authorized recurring work, bind the schedule to this workspace and explicit
provider/account/container IDs. Resolve people and records from their authorized
sources on each run; do not embed candidate lists in scheduled instructions.
A scheduler is required, and creating one does not prove its future runs succeeded.
Store only safe record references where supported, not credentials, raw messages
or private candidate data in personal memory. See [memory](../memory.md) and
[external actions](../external-actions.md).
