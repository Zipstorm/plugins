# Showing the work

Keep progress and hand-offs brief and in recruiter language. Use the client's
task list for steps when available.

## The four moments

- **Plan:** for work that takes time, state the useful steps and what the first
  measurement counts: title family, market, requirements and pool. Mention
  [remembered choices](memory.md) or [connected systems](connectors/README.md)
  only when they affect this work.
- **First result:** when measurement precedes more work, give its scope/date.
  Keep separate markets or title levels separate; compare a wider pool only
  when measured with otherwise identical scope.
- **Hand-off:** give the completed result, up to three caveats and useful next
  steps. A measured requirement trade-off shows both counts, never an invented
  difference/share. Prior contact is an outcome/date/system, not message text.
  Offer a [watch](watches.md) only if an available scheduler can call SeekOut
  and no equivalent watch exists or was declined. Offer remembered defaults
  only if the client supports persistent memory; claim only saves that succeeded.
- **Memory, when asked:** show stored lines grouped by defaults, systems,
  standing work and roles. Forget requested lines; stopping standing work also
  removes its schedule.

For interrupted work, follow [recovery](troubleshoot.md#recover-interrupted-work).

## Rules

Don't share a link to a SeekOut workspace unless the recruiter asks for one: the
work is already in SeekOut. Use only the moments the work needs, once each. A skill's main result can carry
the hand-off and next steps. Never claim unseen progress. Figures retain their
measured scope; use sentence case.

## A page someone else will read

Use [deliverables](deliverables.md) when asked to make, save or share a file.
Naming a reader alone (“for the hiring manager”) calls for forwardable chat
content. Recruiter-only notes stay off the page; chat gets a short hand-off,
not a second copy.

Lead the page with the finding and up to three meaningful figures, then
supported sections and a source ledger. Use shared [status words](status-words.md)
for assessments. Update the same page when supported and identify the new
version and changes.

## The last words

Deliver the result with its caveats and next steps. At most one short line may
follow to point to the first next step; do not repeat findings, names or figures.
