# Troubleshoot

Use for errors, unavailable connections and bug/feedback reports. Fix what can
be fixed, prepare a safe report for the rest, then return failed recruiting work
to its owning skill. Setup handles new connections.

## The check-up

Check together:

- SeekOut account capabilities and the relevant returned failure.
- Tools available here versus systems the recruiter uses; disabled is distinct
  from disconnected.
- Relevant remembered choices/settings and contradictions with live evidence.
- The last error's tool and wording.

Label each **working**, **fixed**, **needs you** (one step), or **not checked**
(reason). Do not infer untested states.

## Fix what you can

Correct contradicted memory and name the correction. An ATS link in SeekOut
is distinct from its own [connector](connectors/README.md). A check-up
does not authorize changes to recruiting records.

## Recover interrupted work

| Failure | Next step |
| --- | --- |
| Missing SeekOut tools | Check whether the connection is disabled in this chat before asking to reconnect. |
| Expired or revoked sign-in | Stop calls and reconnect or involve the connection's admin. |
| Quota or page limit | Honor the returned retry/reset time. Never restart or clear searches, or borrow another chat's search, to bypass it. |
| Exhausted credits | Name the exhausted credit type and continue work that needs none. |
| Transient read error or timeout | Retry once after a short pause; stop after a second failure. |
| Refusal | Make the stated correction; do not repeat an unchanged request. |
| Uncertain write or spend | Follow [external-action recovery](external-actions.md#doing-it-once). |

Preserve completed work and resume only unfinished steps. Use the
[handoff](showing-work.md#the-four-moments) to state the gap and recovery step.
For a quota reset, offer a one-time resume only when an available scheduler can
perform it; otherwise the recruiter can ask again. For an unexplained or
unrecoverable failure, offer the check-up once per conversation.

## What you can't fix: the report

Send bug reports or feedback only when the recruiter requests submission.
Prepare a draft with sanitized task, failing tool/error, time, completed steps and
client. Describe profile mismatches generically, without values. Exclude candidate/
employee identities, profile details, person-linked results/counts, contact data,
connected-system contents, credentials/token links and search IDs.

Query/filter/index details may help reproduce a non-candidate search issue.
Disclose that attachment and omit it if declined or candidate-specific. Reports
cannot be withdrawn once sent and do not carry replies back.

## Close

Lead with the finding, then check states, fixes, next action and report. End
without repeating them ([last words](showing-work.md#the-last-words)).
