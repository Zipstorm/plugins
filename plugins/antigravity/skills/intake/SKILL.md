# Make the role clear

Use these instructions for SeekOut recruiting tasks. For unrelated requests, use the client's usual workflow and leave SeekOut tools idle. If a fresh conversation contains only a role such as “CFO”, ask what the user wants to do.

Follow the starter the recruiter sent, even if Antigravity attaches a different skill. Use the information already in this conversation. A reply to a starter supplies the missing input for that same task.

- **Use SeekOut to find people for my open role and show me why they match.** Use sourcing. If the role is missing, ask “What role are you hiring for?” in chat. A title in reply is enough to run the installed SeekOut connection’s `search_candidates` on that turn. For a public search without a location, explicitly set `request.index` to `"all"` and leave location filters empty. Show up to three returned people in chat with their current title, employer, a detail that supports the requested match, and a profile link when available. For a title-only request, the current title is the evidence.
- **Use SeekOut to compare the talent pool for my role in two locations.** Use reporting. Ask only for the missing role or locations. Measure the same role and criteria in each place. Show each place’s returned count in chat, with its geographic scope. If a place is unmeasured, say which one.
- **Use SeekOut to turn my job description into search criteria I can review.** Use intake. Read the pasted or attached description, or ask for it. Draft the explicit requirements and preferences in chat. Put vague language or unclear priority only under “Questions for the hiring manager”. Ask what observable work the phrase describes before assigning a priority or using a proxy. The supplied description is input to this draft. The MCP instructions for recording a job description in a workspace apply to a requested role plan or save. A search also needs its own request.

Give the recruiter the requested brief, document or role plan. A JD accompanied
by “find people” goes straight to **sourcing**. When a request names a role but
it is not fully clear whether the recruiter wants people now or a plan first
(“help me fill…”, “I'm hiring a…”), ask once before any search or plan: see
candidates now (one search, about a minute) or plan the role first (its overview:
who meets the job description, what would widen the pool and where to search
first, a few minutes).
A request sent from a SeekOut pane button already says which; follow it. For a document, draft from
available facts and mark gaps; do not turn writing into a questionnaire. For a
role plan, clarify the work, who could do it and which decisions remain open.

When the recruiter asks to plan a role, the job description starts its
[role overview](../../references/role-overview.md): build it first, straight
from the job description, without asking. While the overview is the current
work, a follow-up about the role (a what-if, a changed requirement, another
place) changes the overview and saves it again as its next version; a search,
candidate or outreach follow-up belongs to those workflows.

Use the recruiter's explicit target first, otherwise this conversation's
current work item, then visible context consistent with that work. Ask only
if the target remains materially ambiguous; keep unrelated chats and roles
separate.
A follow-up about the current plan revises its trade-offs report and
talent map, including a what-if; it does not create a separate candidate search.

## Establish the brief

Read supplied material and reuse earlier answers before asking. Preserve
explicit requirements, priorities, alternatives and named people; separate
interpretations from agreed facts. Ask only questions whose answers change the
brief. A bare title may need function, level and location; an explicit broad
scope is valid. Clarify whether named people are examples, exclusions or already
in play. Flag contradictory requirements and unrequested proxies without
silently rewriting the bar. Use the shared [criteria](../../references/criteria.md).

Save the supplied description in the role’s workspace for a requested role plan or an explicit save. A request for search criteria to review ends with the draft in chat. Saving the JD alone does not also request a rubric. A role overview's
requirements are the role's rubric: save no separate one beside it. For a role
without an overview, save required, preferred and excluded criteria as the role's
rubric only for requested role planning or screening, or an explicit rubric
request. Use stated requirements without reconfirming them; confirm material
interpretations before saving them. Candidate screening uses the saved rubric.

## Plan and measure

When the recruiter asks for a measured plan beyond the overview (what each
requirement costs across markets, where the talent is), accept a JD, title and
place, or a few lines. Clarify what matters with
your own question tool: at most three questions total, including the opening
for this starter. Reuse answers; ask only about consequential gaps, never
module choices. Keep unknowns explicit; pause only dependent measurements.
A declined or dismissed question pauses the starter until the recruiter supplies
context or asks to continue; never substitute an unrelated role.

Save stated or confirmed criteria, then follow the
[concise report recipe](../../references/report-building.md#choose-and-write):
independent requirement trade-offs and relevant agreed markets. Do not invent
requirements or offices to fill the template. Complete the report, not just the
brief. Keeping the baseline and validating its pool is a valid recommendation;
large counts alone do not justify tightening requirements.

Preserve the agreed baseline; what-ifs stay hypothetical. An explicit requirement
change authorizes revision. Otherwise ask only when the next action needs an
unaccepted change, leaving it pending if the question budget is spent. Recommend
baseline evidence review and at most one conditional alternative: inspect a
variant or draft a hiring-manager push-back. Execute only already-requested steps.
