# Have a useful candidate conversation

Use these instructions for SeekOut recruiting tasks. For unrelated requests, use the client's usual workflow and leave SeekOut tools idle. If a fresh conversation contains only a role such as “CFO”, ask what the user wants to do.

Follow the starter the recruiter sent, even if Antigravity attaches a different skill. Use the information already in this conversation. A reply to a starter supplies the missing input for that same task.

- **Use SeekOut to find people for my open role and show me why they match.** Use sourcing. If the role is missing, ask “What role are you hiring for?” in chat. A title in reply is enough to run the installed SeekOut connection’s `search_candidates` on that turn. For a public search without a location, explicitly set `request.index` to `"all"` and leave location filters empty. Show up to three returned people in chat with their current title, employer, a detail that supports the requested match, and a profile link when available. For a title-only request, the current title is the evidence.
- **Use SeekOut to compare the talent pool for my role in two locations.** Use reporting. Ask only for the missing role or locations. Measure the same role and criteria in each place. Show each place’s returned count in chat, with its geographic scope. If a place is unmeasured, say which one.
- **Use SeekOut to turn my job description into search criteria I can review.** Use intake. Read the pasted or attached description, or ask for it. Draft the explicit requirements and preferences in chat. Put vague language or unclear priority only under “Questions for the hiring manager”. Ask what observable work the phrase describes before assigning a priority or using a proxy. The supplied description is input to this draft. The MCP instructions for recording a job description in a workspace apply to a requested role plan or save. A search also needs its own request.

Deliver the requested assessment, interview preparation, booking, meeting prep or debrief.
Help the recruiter decide what to ask, what to listen for and what to do next.
Use the role's current criteria (its rubric in SeekOut) and supplied candidate
material; use SeekOut to read a SeekOut candidate's full profile. Give a useful
first draft without restarting intake or searching for a new pool. Keep the
same core questions and evidence standard for everyone; tailor probes to the
person's actual work and unresolved requirements.

Use the recruiter's explicit target first, otherwise this conversation's
current work item, then visible context consistent with that work. Ask only
if the target remains materially ambiguous; keep unrelated chats and roles
separate. Keep the candidate, workspace and criteria version explicit across
notes and actions.

An assessment cites the role's rubric and keeps its findings with the
candidate. A follow-up that names no target works on the named candidates
against the role's current criteria.

Choose the work requested:

- [Review candidates](references/evaluate.md): evidence, gaps and a recommendation.
- [Prepare the interview](references/prepare.md): questions, probes, what good
  evidence looks like, and space for notes. Help during the conversation when asked.
- [Book a meeting](references/scheduling.md): any recruiting meeting, with
  colleagues (three free times to pick from) or someone outside the company (their
  booking link by email).
- [Use the calendar](references/calendar.md): update an existing interview and
  attach a question kit or preparation link for the right audience.
- [Prep hiring meetings](references/meeting-prep.md): prepare a brief for selected interviews or hiring meetings. Open recent correspondence or create private appointments when the recruiter requests those actions.
- [Write up and debrief](references/debrief.md): separate answers, observations
  and judgments; identify the next decision.
- [Reference and background checks](references/checks.md) or
  [offers and pre-start handoff](references/closing.md): support the human owners.

Start from the workspace: the candidate is one of a role's candidates, with a
status there. A confirmed booking, and a decision after a debrief, change that
status; set it as the linked reference says and name the workspace.

After a debrief, recommend the decision to record in the pipeline and why
(**pipeline-management**). Carry out an already-requested next step; otherwise
leave it as a recommendation. Record the recruiter's decision, not your
recommendation as though it were theirs.

Missing evidence stays unknown. A profile is not interview performance; a
recommendation is not a hiring decision. Keep private assessment notes out of
candidate invitations. Use **outreach** for requested messages and
**pipeline-management** for requested ATS changes; claim a booking, attachment
or saved decision only when its action confirms it.

For host forms, presentation and connected systems, read [client guidance](client-adapter.md).
