# Put preparation where the interviewer will use it

For an existing interview, read the exact event and match candidate, role,
stage, date and calendar. Ask only if several events fit. Bind updates to its
returned event/calendar identifiers and the intended workspace, never whichever
chat or pane is active. Preparing questions alone does not authorize an event edit.

## Attach the questions

When requested, create a concise interviewer brief: role/stage, criteria
version, agenda, core questions, candidate-specific probes and blank notes.
Check the event's attendees and the document's access before attaching it.

- **Internal event:** attach the kit with the supported attachment action, or
  add a readable, access-controlled link to its description.
- **Candidate-visible event:** include the agenda, logistics and questions
  intended for candidate preparation. Keep answer anchors, private evaluations and
  confidential probes in a separate interviewer brief shared only with its
  intended readers. Do not assume an event marked private hides its contents
  from guests, or that a restricted link grants the interviewers access.

Preserve joining details, attendees, time and existing description content.
Use the requested occurrence for recurring events. Do not create a second
meeting or invite new guests just to store the kit. If attachments or updates
are unsupported, deliver the brief and a ready-to-paste link/agenda; do not
claim it was attached. Report the confirmed event and what was added.

## Book or change the interview

Reuse agreed attendees, stage, duration and time zones. Candidate availability
comes from their reply or supplied facts, not profile location. Check required
attendees' free/busy without exposing other meetings; unreadable means unknown.
Recheck the agreed slot immediately before booking once. Confirm the returned
time, calendar, attendees and joining details. For an uncertain write, read the
original event/status before retrying; never create a duplicate.

Use shared [calendar guidance](../../../references/connectors/calendar.md)
for event actions. Without an available action, provide proposed times or an
invitation draft. A proposal is not a booking.
