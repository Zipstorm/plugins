# Answer from the right pipeline

Use the recruiter's chosen ATS connection, exact requisition and requested
window. Prefer its own connector; otherwise use the pipeline reads SeekOut
actually provides. A supplied export is dated file evidence, not a live read.
Public profiles and workspace shortlists cannot stand in for the ATS.

Resolve the connection's actual job, stage, status and reason values before
filtering; names and casing vary. Preserve existing filters or explicitly
remove them. Use the [ATS pack](../../../references/packs/ats.md) for SeekOut's
filter semantics and provider distinctions. Never combine two sources or
connections into an unlabeled total.

Distinguish people from applications. A sample's stage figures count
applications among the people sampled; top-value breakdowns are not totals.
Scope by requisition before aggregating. Use an exact scoped count when the
decision needs one; investigate a count smaller than the comparable sample.
Preserve completeness warnings and empty fields. Names come from actual records.

Current stages show a snapshot, not conversion, time in stage or transitions
within a period. Those require returned historical metrics or event history
with definitions. Last activity is inactivity, not stage entry or an overdue
promise. Ask for the inactivity threshold if missing; explain when whole-month
filters broaden a days/weeks request. Do not rank recruiter workload beyond the
sample unless coverage supports it.

For several open requisitions, give one scoped row per role. If market context
is requested, reporting measures each role's own criteria and geography. Keep
market and ATS counts separate; never divide them into a rate or use an arbitrary
pool-size threshold to declare a role at risk. Label bottleneck hypotheses and
what would test them. Deliver partial coverage with the unmeasured roles named.

Finish with source/read date, scoped answer and what the evidence cannot show.
