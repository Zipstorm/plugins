# Apply the requested record change

Read the exact current record and permitted values. Keep candidate, application,
job, posting and activity identities distinct: a stage belongs to an application.
Show the old/new values and the human decision or evidence behind the change.
Explicit instructions already authorize their scope; ask only about unresolved
choices or a required confirmation. Change no unrelated fields.

Use the actual write and [external-action recovery](../../../references/external-actions.md).
Read back when available; report confirmed changes, discrepancies and unresolved
items. Without a suitable write, provide a clearly unsaved proposal. Never create
a prospect, application, requisition or posting as a substitute for an update.
For a requested merge/delete, resolve the exact records and intended survivor
before the destructive action; never delete merely because names match.

## Dispositions and notes

Record the human decision, not your assessment. Inactivity alone is not rejection;
a recruiter can explicitly decide to close a defined set. Resolve that set and
its applications, then map the stated reason to the connection's permitted code.
Keep role closure, withdrawal, missing evidence and demonstrated mismatch distinct.
“Position filled” must not become a candidate-fit failure or “Hired.” If no code
fits, propose a faithful available general code plus factual note, or ask about
a material ambiguity. Flag discriminatory reasons instead of laundering them
into neutral wording. Preserve the decision source and date.

Notes are short, dated facts relevant to the role. Exclude contact details,
pay history, protected/health details and verbatim personnel feedback.

## Requisitions and postings

Distinguish proposed from approved changes. For hold, cancellation or rescope,
identify affected applications, interviews, offers, postings, outreach and
the role's workspace reports before writing. Update only what was authorized; list other
systems needing follow-up. A brief edit does not update those systems.

Use approved location, pay, dates and application destination. Preserve live/draft
versions and channel receipts. Treat linked measurements and assessments as
potentially stale after criteria change; retain originals and route the role's
next report version to intake/sourcing. Pay-transparency and candidate-data obligations
follow [shared safeguards](../../../references/us-recruiting-safeguards.md) and
the responsible policy owner, not a canned jurisdictional assurance.
