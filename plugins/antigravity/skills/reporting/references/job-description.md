# Job description

A workspace keeps one job description, and every change to the job is a new
version of it. Before starting one, check whether the workspace already has
one; if it does, revise that report instead, and say in one line what the new
version changed (for example "Kubernetes moved to nice to have; location now
remote US").

Save one only when the recruiter gave a job description or notes about the
role: when planning a role on your own, anywhere else only when they ask.
A role name alone is not a job description; never save one from it.

A pasted job description usually arrives with the page it was copied from.
Clean it before saving, without asking: keep a link's words but drop the link
and every URL (tracking parameters included), markdown or HTML escapes (such
as `&#x20;`, `\&` or stray `**`), and the job board's own lines that are not
the job (applicant counts, "posted 1 week ago", "Promoted by hirer",
"Responses managed off LinkedIn", "Show more", Apply buttons). Keep the facts
those lines carry about the job, such as its place and work arrangement, in
the key-facts line. The recruiter pastes once and waits for the work: never ask
them to clean or confirm it.

Save it as the report's body, laid out in markdown as a real job posting:

- `# ` and the job title first;
- one bold line of the key facts the text gives, joined by ` · `: company,
  location and work model, employment type, pay range (for example
  `**Northwind · Seattle, WA (hybrid) · Full-time · $170k–$210k**`);
- then each section under a `## ` heading, in this order, leaving out any the
  recruiter's text does not support: About the role (a short paragraph),
  Responsibilities, Requirements, Nice to have, Compensation and benefits,
  About the company (a short paragraph). Write the points of the middle
  sections as bullets, one point each.

A job description is its own report and holds only its body: no modules,
findings or recommendations. Keep the recruiter's own words and order
within a section; fix only spacing and obvious typos. Never invent a
requirement, a pay range, a benefit or a section with no source text, and never
turn a preference into a requirement.

When revising, write the whole new text again in place of the old, so the new
version holds only the current job. A job description holds no figures,
findings, recommendations or next steps.
