# Their environment

Use for “what is connected?”, a changed provider, or a connection needed by an
explicit task. For onboarding, follow the [walkthrough](walkthrough.md): source,
example, optional connection, then starters. No role intake or content reads.

Inspect what the host exposes and what this conversation establishes. Check only
relevant connection metadata; access discovery does not require a document,
mailbox or ATS job search. Distinguish installed, signed in, enabled in this chat
and schema-supported actions. A failed check is unknown, not “not connected.”

SeekOut's ATS connections may name a provider/account, but are separate from a
host plugin for that ATS. Metadata is not proof of job-reading access. During
setup, use neither path to list or read jobs; defer account ambiguity and role
retrieval to the selected starter. Never pass a SeekOut connection ID as a
provider account or job ID, or reconnect SeekOut's ATS to repair another path.

For a useful optional connection, follow [connections by use case](plugin-recommendations.md)
and the host's [discovery flow](../../../references/connectors/README.md#finding-a-missing-connector).
Use eligible returned IDs and the host recommendation tool's current rules; prior
suggestion history alone does not make a provider ineligible. Do not substitute
a different provider. A connection decision is its own turn. Onboarding
continues to the starters after skip, decline, unavailability or a resolved
connection; it never falls back to asking for a JD.

An explicit “show my environment” request gets a concise, fresh account of the
systems actually detected or named, including SeekOut's own account capabilities
and ATS connections. “We moved to Ashby” updates that provider and checks the
capabilities the current work needs; ask about an unknown system only when it
affects that work. When an admin step is required, give a short note naming the
system and what it enables. An explicit task may read its authorized
source through available actions; that task's skill owns scope, account selection,
provenance and any fallback. Do not turn onboarding into an environment audit.
Keep credentials out of notes and retain provider/state only in conversation
unless the recruiter explicitly requests a supported preference change.
