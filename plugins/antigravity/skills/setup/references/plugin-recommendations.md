# Connections by use case

For onboarding, read after the source answer, before the optional connection
step. Setup's final decision is the starters; no source content is read here.
For an explicit recruiting task, recommend only what that task needs.

| Chosen source or task | Benefit to explain |
| --- | --- |
| Google Drive, SharePoint, Notion, Box or Dropbox | Existing JDs, leveling guides and intake notes can clarify hiring criteria. |
| Slack or Teams | Hiring-team conversations can explain the priorities behind a vague requirement. |
| Named ATS | Requisition context can clarify a target; confirm the plugin's advertised role-reading capability before recommending it for that purpose. |
| Outreach through a connected email app | Gmail or Outlook Email can provide prior threads or supported draft/send actions. SeekOut workspace outreach does not need a mail plugin. |
| Explicit interview scheduling | The recruiter's Google Calendar or Outlook Calendar can provide supported scheduling actions. Do not infer this need from onboarding. |
| Intake or interview transcripts | Their meeting-notes provider, such as Fireflies, Otter.ai or Zoom, can supply what the hiring manager actually said. Only when they mention transcripts. |
| Pipeline tracking | Their ATS by name for stages, applications and requisition records. Saving and listing candidates in a SeekOut workspace needs no extra plugin. |

These are discovery terms, not a catalogue of available integrations. Another
named provider can replace an example. SeekOut candidate search, market measurements
and saved candidates do not by themselves require extra plugins.

## Check the selected source, then make one useful offer

1. Reuse the actual provider named or selected. Inspect connected/deferred action
   metadata first. Do not infer Gmail from Drive, Outlook from Teams, or a usable
   ATS job reader from SeekOut's connection inventory. No private content reads
   during setup, including after connection.
2. If needed, search the host's directory for that provider. Verify identity,
   installation eligibility and relevant advertised capability. Recommend only
   a matching eligible returned ID through the host's real recommendation action;
   mentioning a name or searching alone does not show a connection card. Never
   substitute an unrelated ATS or invent a plugin. Setup's source choice permits
   this recommendation without another permission question.
3. Use the recommendation tool's current eligibility rules. Do not add a SeekOut
   cooldown or suppress the selected source merely because suggestion history
   exists or a suggestion count is positive. History does not establish a pending
   card, a current decline or a host restriction. If the host permits this offer,
   make it; directory discovery alone is not the recommendation. A suggestion is
   not installation, sign-in or verified read access. An ATS host plugin is
   separate from the existing SeekOut ATS connection.
4. When a card is shown, keep the concrete illustrative example in the final
   response accompanying it and end the turn. Wait for the connection decision;
   do not compete with a starter question or poll. After Not now or a resolved
   connection, advance to the starters using the same question mechanism.
5. With no eligible card, defer the connection and advance. Say “You can connect
   this source later” when appropriate, without exposing suggestion history.
   Do not add a JD, provider, account, input-method or example-role question.

Refresh metadata after a reported connection, without claiming content was read.
Keep the verified state and the decision in conversation for the later selected
workflow. Outside onboarding, follow the owning task's scoped read and fallback;
installation does not authorize arbitrary private-content access.

## Connection advice outside onboarding

When the recruiter asks which connections would help, steps 1–3 apply; there is
no card to wait on and no starter question. Combine overlapping needs and
recommend at most three, the one that enables their next task first. Never
recommend competing providers (Gmail and Outlook, Drive and SharePoint) unless
they use both. Give one short reason tied to what they said, such as “SharePoint
would let a hiring plan start from your existing JDs.” A directory match alone
does not prove it can send mail, update an ATS or book an interview. When the
search returns no suitable plugin, say it was not found in this search, not that
none exists. Respect a request for advice only: no installation or reads.
